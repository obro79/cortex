# Visual Reference

Linear Intake is the close visual and structural reference for the Cortex
landing page: https://linear.app/intake

The goal is to borrow the product storytelling discipline, not the exact
content, screenshots, layout, or brand assets.

## Traits To Use

- Numbered chapters such as `1.0`, `1.1`, `1.2`, and `2.0`.
- Small figure labels such as `FIG. 1.1`.
- Short declarative headlines.
- Dense product panels instead of decorative illustrations.
- Real workflow visuals that show the product doing work.
- Quiet premium tone with restrained copy.
- Repeated rhythm:
  - product claim,
  - visual proof,
  - focused capability explanation.
- Multiple smaller product moments instead of one generic hero screenshot.

## Traits To Avoid

- Do not copy Linear's wording.
- Do not copy Linear's exact page layout.
- Do not copy or recreate Linear product screenshots.
- Do not use Linear-specific product claims, examples, issue IDs, or customer
  quotes.
- Do not make Cortex feel like a generic dashboard product.
- Do not use decorative abstract graphics where a product panel can explain the
  workflow.

## Cortex-Specific Translation

- Replace Linear's product-operations story with an agent-context story.
- Replace issue intake visuals with context retrieval visuals.
- Use MCP, CLI, and UI as first-class access paths.
- Show Slack, GitHub, Linear, and repo docs as live source systems.
- Show evidence packs, freshness, and permission decisions as the trust layer.
- Use source-object and evidence-detail panels as the main product visuals.

## Product Visual Inventory

1. Hero product-system map:
   - engineer prompt,
   - agent or CLI,
   - Cortex,
   - connected sources,
   - cited context bundle.
2. Context request panel:
   - query input,
   - source filters,
   - mode chips for MCP, CLI, UI,
   - returned context.
3. Retrieval source panel:
   - Slack thread,
   - GitHub PR,
   - Linear issue,
   - repo doc.
4. Evidence pack panel:
   - cited chunks,
   - source coverage,
   - freshness,
   - permission exclusions.
5. Agent trace panel:
   - request,
   - retrieval,
   - filtering,
   - evidence,
   - response.
6. Source health matrix:
   - connected sources,
   - sync status,
   - cursor,
   - backfill,
   - reauth or stale warnings.

## Copy Voice

- Prefer direct claims: `Get the context before code changes.`
- Prefer concrete nouns: `evidence`, `source`, `trace`, `freshness`,
  `permission`.
- Avoid broad claims like `unlock knowledge` unless paired with a concrete
  product visual.
- Keep section text short enough that visuals carry most of the explanation.
